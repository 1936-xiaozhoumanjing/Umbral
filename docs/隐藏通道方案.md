# /proc/umbral 彻底隐藏方案（1.65.0-chan）

## 一. 现状与目标

```
现状：/proc/umbral 目录存在，23 个子节点对任何进程可读（stat/ls 都成功）
目标：/proc 下不存在 umbral 这个名字，readdir 看不到、lookup 也 ENOENT；
      所有命令改走一个随机挑选的冷门 /proc/sys 文件（劫持通道）
```

## 二. 三层实现

### 层 1：模块身份隐藏（已生效，前提是加载时带 hide=1）
```
sk_hide_self():
  · list_del(&THIS_MODULE->list)     → /proc/modules、lsmod 里消失
  · kobject_del(&mkobj.kobj)         → /sys/module 里消失
  · 清 tainted_mask 的 0x200         → /proc/sys/kernel/tainted 干净
  · sk_hide_proc_dir()               → 包装 /proc 根 i_fop，readdir 过滤 "umbral"
```

**关键教训**：`sk_hide` 曾默认 0，而 init 用
`syscall(SYS_init_module, buf, sz, "")` 加载（空参数）
⇒ 隐藏代码从未执行。现在：
```
sk_hide 默认 = 1
init: load_module("/umbral.ko", "hide=1");
      load_module("/propfix.ko", "");   ← propfix 没有 hide 参数，不能带，否则加载失败
```

### 层 2：劫持通道（1.65.0-chan 新增）
```
安装：sk_chan_install() 随机挑一个候选（21 个），filp_open(O_RDWR) 成功就装 fops
候选池（全部实测存在于 NX789J / 6.6.30）：
  /proc/sys/vm/  watermark_boost_factor  percpu_pagelist_high_fraction
                 admin_reserve_kbytes    user_reserve_kbytes
                 watermark_scale_factor  extfrag_threshold
                 page_lock_unfairness    stat_interval
                 oom_dump_tasks          mmap_rnd_bits
                 mmap_rnd_compat_bits
  /proc/sys/kernel/ sched_deadline_period_min_us  sched_deadline_period_max_us
                 sched_rr_timeslice_ms   soft_watchdog  nmi_watchdog
                 warn_limit  overflowuid  overflowgid  ngroups_max  max_lock_depth
黑名单（绝不劫持）：
  stat meminfo cpuinfo vmstat loadavg uptime version modules filesystems
  ns_last_pid tainted randomize_va_space core_pattern modprobe hostname
  domainname osrelease ostype panic* printk* sched_* watchdog* hung_task*
  perf_* drop_caches swappiness overcommit* max_map_count min_free_kbytes
  dirty_* vfs_cache_pressure mmap_*
  /proc/self 下全部、/proc/<pid> 下全部（libtersafe 会扫）

协议：
  写 0xEF 0xBE + 子命令（"ver" / "backend" / "mode" / "status" / "stats" /
                        "grants" / "diag" / "token" / "selftest" / "grant <内容>"）
  读 同一文件 → seq_file 型命令用 single_open(f, 原 show, NULL) + seq_read 转发
  非 magic 写入 → 原样转发给备份的原始 write（原功能不受影响）
  open → 有原 open 就转发，绝不返回 EACCES/ENOENT
```

### 层 3：完全不建目录（编译开关，待切换）
```
#ifndef SK_NO_PROCDIR
#define SK_NO_PROCDIR 0      /* 0=保留 /proc/umbral；1=彻底不建 */
#endif

两套产物：
  umbral_s.ko           229,160 B  md5 a8dcec22180773546072f86c8f9722dc   (SK_NO_PROCDIR=0)
  umbral_noprocdir.ko   145,264 B  md5 b577ddabe06a2e7a88eb1f1dd5deb02c   (SK_NO_PROCDIR=1)
```

## 三. 管理器侧适配

```
ModuleControl.readDirect / writeDirect：
  path 含 "/umbral/" → 自动改走通道
    · 探测：扫 /proc/sys/vm 与 /proc/sys/kernel（同一份黑名单），
            写 magic+"ver"，读回含 "." 即命中并缓存
    · 双路回落：通道失败 → 走原来的直接读写（1.64 授权事故就是缺了这一步）
    · /proc/umbral 仍存在时视为"模块无通道"，不探测（兼容旧 ko）

已迁移到统一封装的类：
  ModuleControl / ModuleRunner / Guard / MainActivity / UmRepoActivity / GrantsPersist

未迁移（shell 里拼路径，需读 /data/data/io.umbral/chan 拿路径）：
  SuProbe / LauncherSession
无需迁移：
  KpmRepository（设备上根本没有 /proc/umbral/kpm 子目录，属历史遗留）
```

## 四. 验证脚本

```
tools/verify-chan.sh（已推到设备 /data/local/tmp/）
  1. 扫候选、写 magic、读回 → 报告通道是否命中及命中路径
  2. /proc/umbral 是否存在、ls /proc 里 umbral 计数
  3. lsmod / /sys/module / /proc/modules 里 umbral 计数、tainted
  4. 结论：彻底隐藏达成 / 通道可用但目录仍在 / 通道未就绪
```

## 五. 切换步骤（通道验证通过后）

```
1. 确认 verify-chan.sh 输出"通道命中"
2. 把 umbral_noprocdir.ko（b577ddab…）作为 umbral.ko 铺进 11 个 KMI
3. 重编 APK → 重打 init_boot → 刷入 → 重启
4. 再跑 verify-chan.sh：
     期望 /proc/umbral 不存在、ls /proc 计数 0、通道命中、lsmod/sys_module/tainted 全干净
```

## 六. 已知坑（血泪）

```
· 改 KCFLAGS 但没改源码时，make 不会重编 → 必须 make clean，
  否则"无目录版"其实是旧产物（229,160 B 那次就是）
· 模块一旦 hide=1 生效，rmmod 会失败（链表已摘）→ 换模块只能重启
· 模块"自卸载"（work 里 call_usermodehelper 调 rmmod）会 panic，禁止使用
· 管理器任何"改道"逻辑都必须带回落，否则旧模块上功能全挂
```
