# 影核 V1.3 更新公告 —— 内核兼容性

**发布日期：** 2026-11-13
**版本：** 管理器 V1.3 / 内核模块 1.43.1

---

## 一、这次更新只做一件事：让模块在更多机型上真的能加载

以前的问题：模块只在你自己的机器上验证过，换一台就报
`version magic mismatch` 或 `disagrees about version of symbol`，装上去等于没装。

V1.3 把这两条路都打通了。

---

## 二、支持的 KMI（内核接口）目录

管理器内置 **11 个 KMI 目录**，安装时会按你的内核版本自动挑：

| Android | 内核 | 目录 |
|---|---|---|
| 11 | 5.4 | `android11-5.4` |
| 12 | 5.10 | `android12-5.10` |
| 13 | 5.10 | `android13-5.10` |
| 13 | 5.15 | `android13-5.15` |
| 14 | 6.1 | `android14-6.1` |
| 15 | 5.15 | `android15-5.15` |
| 15 | 6.1 | `android15-6.1` |
| 15 | 6.6 | `android15-6.6` |
| 16 | 5.15 | `android16-5.15` |
| 16 | 6.1 | `android16-6.1` |
| 16 | 6.6 | `android16-6.6` |

**说明：** 有些厂商会把旧内核（5.15）装到新系统（Android 16）上，
官方 GKI 并没有这种组合，所以我们额外做了别名目录来覆盖这类机器。
这类机型属「尽力支持」，不保证一定能加载。

## 三、每个 KMI 都是「真 CRC」，不是占位

内核开了 `CONFIG_MODVERSIONS` 时会校验模块里每个符号的版本指纹（CRC）。
模块如果带的是空指纹，内核会直接拒载。

V1.3 里 5.4 / 5.10 / 5.15 / 6.1 / 6.6 **五个分支全部用对应内核源码完整构建过**，
模块里带的是真实 CRC：

| 内核分支 | 符号版本信息大小 |
|---|---|
| 5.4 | 4,544 字节 |
| 5.10 | 5,568 字节 |
| 5.15 | 5,568 字节 |
| 6.1 | 5,632 字节 |
| 6.6 | 4,736 字节 |

**这意味着：只要你的内核保留 GKI 的导出符号 ABI（绝大多数机型都是），
模块的 CRC 就与你的内核一致，能直接加载。**

## 四、每个 KMI 都准备了两套模块

| 变体 | 什么时候用 |
|---|---|
| `umbral.ko` | 正常情况，带 CRC |
| `umbral_nomv.ko` | 你的内核 CRC 校验过不去时，自动改用这一套 |

安装时会**两份都写进 ramdisk**，启动时按下面的顺序尝试加载：

```
1. finit_module 正常加载
2. finit_module + 忽略版本/CRC 校验
3. init_module（兼容老内核）
4. 改用 umbral_nomv.ko 再来一遍
```

**只要有一条成功，模块就起来了；全都失败也不会影响开机。**

---

## 五、vermagic 会自动改成你机器的值

模块里的 `vermagic` 必须和你的 `uname -r` 一字不差。
V1.3 在打包时会读取当前内核版本并自动改写，所以你不用手动处理
`version magic 'X' should be 'Y'` 这类报错。

## 六、仍然可能失败的机型（如实告知）

```
· 厂商改过内核导出符号（尤其内核版本带 -dirty 的自编译内核）
· 非 GKI 组合（如 Android 16 + 5.15）且厂商做过深度改动
· 内核强制要求模块签名（CONFIG_MODULE_SIG_FORCE=y）
```

遇到这几种，模块不会崩系统，只会**加载失败**，管理器显示「未刷入」。
如果你愿意帮忙定位，把 `dmesg` 里 insmod 那几行发出来，我们能判断属于哪一类。

---

## 七、怎么确认自己这台是哪种情况

安装后打开管理器：

```
模块页 → 状态
  已刷入       → 加载成功
  未刷入       → 看诊断页的能力自查，会写明失败原因
```

内核侧可查：
```bash
su -c 'cat /proc/umbral/version'     # 有输出就是成功
su -c 'ls /proc/umbral/'             # 节点列表
```

## 八、一句话总结

> V1.3 把 5.4 / 5.10 / 5.15 / 6.1 / 6.6 五个内核分支都做成了
> **带真实符号 CRC 的正规模块**，并准备了无 CRC 的备用变体和四级加载回退，
> 同时自动适配 vermagic —— 换机型不再等于「装完没反应」。
